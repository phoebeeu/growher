# 推进｜MVP PRD v2（单一项目版）

版本：v2.0  
日期：2026-08-15  
状态：开发前确认稿

## 1. 产品定义

「推进」帮助孕期女性在整个孕期只推进一个可量化、可验收、最终有成果的个人项目。系统在固定时间温柔地陪她完成当天的一步，并用缓冲日、最低底线和成果板适应孕期状态变化。

## 2. 目标用户与场景

- 用户：孕期女性；项目可以与宝宝有关，也可以完全服务于自己。
- 场景：用户每天在固定提醒时段打开网页，用较短的一段时间推进一个已经承诺的项目。
- 典型项目：100 天写给宝宝的日记、完成一套课程、制作一组插画、整理一本小册子、完成一组播客或其他有明确产出的项目。

## 3. MVP 核心原则

1. 同时只能有一个进行中的项目。
2. 每天只推荐一个当前行动，不生成任务清单墙。
3. 用户在其他工具中完成真正作品，推进负责计划、陪伴、记录和反馈。
4. 计划有标准任务和最低有效任务；完成最低任务也算完成，但在成果板上以浅色显示。
5. 休息日和缓冲日不打断连续记录；不使用“失败”或羞耻性提示。
6. 用户每天都能看到已有成果、今天行动和一句鼓励，不必等到周末才获得反馈。

## 4. 五个核心页面

| 页面 | 用户唯一要完成的事 | 使用频率 |
|---|---|---|
| 1. 目标成型器 | 把模糊想法变成一个可执行、可验收的单一项目 | 首次及重新签订契约时 |
| 2. 项目计划与契约 | 确认阶段、未来 7 天、缓冲日和最低底线，并决定现在开始或先保存 | 首次及正式调整时 |
| 3. 项目首页 | 看见已有成果，选择今天的状态并接受唯一行动 | 每日默认入口 |
| 4. 陪伴执行 | 完成标准行动或最低行动，并留下可选记录 | 每日执行时 |
| 5. 成果板 | 查看完整进度、连续记录、里程碑和附件 | 每日可查看，非每日必填 |

每日主路径：`固定提醒 → 项目首页 → 陪伴执行 → 点亮成果格 → 回到项目首页`  
首次路径：`目标成型器 → 项目计划与契约 → 项目首页`

## 5. 目标成型器

用示例和短问答引导用户，不要求用户先理解“可量化项目”等术语。至少收集：

- 我想完成什么最终成果。
- 需要完成多少个单位（天、篇、节、张、件等）。
- 希望在多少天内完成；周期限制为 14–280 天。
- 完成后的最低可接受质量是什么。
- 标准任务是什么；最低有效任务/底线是什么。
- 每天可投入的大致时间：由 AI 推荐，用户可调整。
- 固定见面时间：每日同一时段，允许前后 60 分钟完成。
- 是否接受系统建议的缓冲日（通常为总周期的 10%–15%）。

AI 必须检查：单位、周期、每日时间和最低底线是否可行。若不一致，先要求用户降低数量、延长周期或调整底线，不能直接生成不可完成的契约。

正式开始前显示项目契约卡，提供「现在开始」和「先保存」。

## 6. 计划与缓冲规则

- 计划页显示整体阶段、阶段目标、缓冲日数量与分布，并只详细生成未来 7 天。
- 缓冲日提前明确显示，例如“已为你预留 12 个缓冲日”，不提前强调失败后果。
- 正常推进：完成标准任务。
- 今天轻一点：完成预先约定的最低有效任务，记为完成，成果格浅色点亮。
- 今天休息：不要求最低任务，消耗一个缓冲日，不打断连续记录。
- 错过一天：系统自动将后续任务重新分配到缓冲日，不要求用户手动补作业。
- 缓冲日剩余 3 天时，温柔询问是否降低频率或延长截止日期。
- 缓冲日用完：显示“原计划未按期完成”，提供延长日期、降低总量或结束当前版本；不显示“失败”。
- 中途不能日常随意修改最低底线；用户可以发起一次“重新签订项目契约”，系统重新计算计划。
- 同一用户只能有一个进行中的项目；项目可以暂停或结束当前版本并保存已有成果。

## 7. 每日体验

- 每日固定提醒以邮件为主；用户授权后可补充浏览器通知。
- 项目首页只提供三个状态入口：`正常推进`、`今天轻一点`、`今天休息`。
- 首页始终展示：孕周、已有成果摘要、今天唯一行动、一句不催促的鼓励。
- 行动时长来自初始契约；AI 推荐，用户在目标成型时调整，不让用户每天重新排计划。
- 真正作品在外部工具完成；打卡时可附一段记录、照片或作品链接。

## 8. 成果板

- 统一使用进度格表达周期累计成果。
- 标准完成为实心格；最低底线完成为浅色格；休息/缓冲保留记录但不制造负面红点。
- 主题按项目类型变化：写作、学习、创作、整理；结构不变，图案可变。
- 显示累计完成量、剩余量、连续记录、阶段里程碑和附件。
- MVP 支持导出可分享的成果图片；完整 PDF/项目包可后续增加。

## 9. 孕期相关内容边界

首页可显示孕周和一条经过审核的温柔关怀语。MVP 不承担营养、诊断、治疗或个性化医疗建议，不接入医疗判断，不用健康内容淹没项目推进主线。

## 10. 明确不做

- 多项目并行、多目标工作台、复杂周历和日历同步。
- 每日多任务清单、能量分数矩阵、连续追赶任务。
- 排行榜、打卡火焰、逾期红点、倒计时恐吓、失败标签。
- 自动替用户修改固定契约或自动移动用户已确认的内容。
- MVP 阶段的医疗建议、营养处方、诊断、社交社区和付费体系。

## 11. MVP 验收标准

1. 新用户在 5 分钟内能从想法得到一张可读的项目契约卡。
2. 用户每天打开首页即可看到成果摘要和唯一行动。
3. “轻一点”和“休息”不需要重新规划，也不会造成羞耻反馈。
4. 100 天项目能展示阶段、未来 7 天、缓冲日、标准/底线完成和剩余量。
5. 用户可以暂停或结束当前版本并保留成果；始终只有一个进行中的项目。
6. 关键流程在手机宽度和桌面窄壳中均可完成，无横向滚动。
